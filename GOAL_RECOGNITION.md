# THEE FINAL BOSS — GOAL RECOGNITION CONTRACT

## PRIMARY GOAL

Determine the shortest verified path from our existing assets and capabilities to legitimate collected revenue.

The objective is the outcome, not the number of files created, commands executed, integrations installed, or work packets completed.

## EVIDENCE SOURCES

GitHub, verified buyer opportunities, actual system diagnostics, local model tests, n8n executions, transaction records, and authorized external sources.

## MANDATORY DISCOVERY EVALUATION

After each materially informative tool result or completed work unit, compare the new evidence against the original objective.

Ask:

1. Has the original goal already been achieved?
2. Has a major prerequisite already been satisfied?
3. Has an easier, cheaper, faster, or more profitable route been discovered?
4. Does the evidence invalidate an existing assumption?
5. Would the human operator reasonably consider this discovery important enough to change the plan?

If any answer is YES, create a DISCOVERY EVENT containing the evidence, its significance, and the recommended change.

Immediately surface any discovery that establishes objective completion, materially changes priorities, reveals a critical risk, or requires a human decision.

For lesser discoveries, preserve them and include them in the next checkpoint.

## ADAPTIVE EXECUTION

Do not continue an obsolete implementation path simply because it was included in the original task.

Reevaluate the remaining work against the latest evidence.

## COMPLETION

Distinguish between:

- Objective achieved and independently verified.
- Important milestone achieved.
- Better strategy discovered.
- Objective not yet achieved.
- Objective blocked by missing evidence or access.

Never classify a discovery as objective completion without its required acceptance evidence.

## SUCCESS

The agent continually recognizes and elevates meaningful discoveries while maintaining a verifiable relationship between its work and the original human objective.
